# 8주차 54일차 — 입력 오류와 자료 부족 처리

## 목적

정상적인 빈 조회 결과와 자료 부족·잘못된 요청을 구분한다.

## 변경한 코드

- exercises/api-day52/main.py: 가격 조회 입력·자료 검사 보완.
- exercises/api-day54/check_errors.py: 임시 자료에서 거래일 한 행을 제외하는 검사.
- 53일차 결과 조회 코드는 변경하지 않고 기존 오류 동작을 확인했다.

## 구현과 확인

- 2025년을 벗어난 요청: 기간 수정 안내를 브라우저에서 확인했다.
- 내용이 없는 CSV: 503과 빈 파일 설명을 확인했다.
- 열 이름만 있는 CSV: 503과 데이터 행 부족 설명을 확인했다.
- date 열 누락: 503과 필수 열 누락 설명을 확인했다.
- 존재하지 않는 날짜: 503과 잘못된 날짜 설명을 확인했다.
- 날짜 결측: 503과 날짜가 빠진 행 설명을 확인했다.
- 임시 자료에서 2025-01-03 한 행 제외:
  원본 242행·임시 241행, 503과 누락 날짜 안내를 확인했다.
- 정상 원본의 주말 조회: 0행과 빈 리스트를 확인했다.
- 정상 원본의 1월 2일~6일 조회: 2일·3일·6일의 3행을 확인했다.
- 없는 실행 ID 조회: HTTP 404를 curl로 확인했다.
- 잘못된 실행 ID 형식 조회: HTTP 422를 curl로 확인했다.

CSV 오류 검사는 임시 폴더로 조회 경로를 바꿔 함수를 직접 호출했다.
모든 CSV 오류를 브라우저에서 HTTP 요청으로 확인한 것은 아니다.

## 거래일 기준과 범위

34일차의 2025년 휴장일 목록을 같은 기준으로 사용했다.
평일에서 휴장일을 제외해 요청 기간의 예상 거래일을 구성했다.

- 주말·휴장일의 빈 결과는 정상이다.
- 예상 거래일의 행이 없으면 자료 부족으로 조회를 중단한다.
- 누락 원인이 수집 실패인지 거래정지인지는 별도 확인이 필요하다.
- 이번 검사가 가격·거래량의 정확성이나 모든 자료 오류를 보장하지는 않는다.
- 원본 CSV 수정·외부 데이터 수집·실제 주문은 없었다.

## 검사 파일 상태

실습 중 임시 입력을 바꾸며 각 오류를 확인했다.
현재 check_errors.py에는 거래일 한 행 누락 검사가 남아 있다.
이 파일 하나가 앞서 확인한 모든 오류를 다시 검사하는 것은 아니다.

## 수정한 문제

- 필수 열 변수의 정의 위치를 수정했다.
- 임시 입력과 기대 오류 설명이 서로 달랐던 부분을 맞췄다.
- 검사 코드를 가격 조회 파일에 넣어 발생한 자기 참조 오류를 수정했다.
- 가격 조회 파일을 복원하고 두 파일의 역할을 구분했다.
