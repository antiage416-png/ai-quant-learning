# 29일차 — 한국 주식 데이터 수집 계획

## 학습 목표
수집할 종목, 기간, 제공처와 가격 기준을 정한다.
이 계획을 이후 API 이용 준비와 데이터 수집의 기준으로 사용한다.

## 전체 계획에서의 위치
- 전체 24주 중 5주차: 한국 주식 일별 데이터 수집·정리
- 29일차: 수집 범위 선정
- 다음 30일차: API 이용 권한과 인증키 준비
- 이후 31일차: 데이터 열과 자료형 설계

## 수집 대상

| 종목명 | 종목코드 |
|---|---|
| 삼성전자 | 005930 |
| SK하이닉스 | 000660 |
| 현대차 | 005380 |
| NAVER | 035420 |
| 신한지주 | 055550 |

- 이번 실습은 위 5개 종목으로 진행한다.
- 종목코드는 앞자리 0을 보존하는 문자열로 다룬다.
- 다른 관심 종목으로 변경하는 작업은 이후 확장 실습으로 진행한다.

## 수집 기준

| 항목 | 기준 |
|---|---|
| 제공처 | 한국투자증권 Open API |
| 조회 API | 국내주식기간별시세(일·주·월·년) |
| 시장 | KRX |
| 시작일 | 2025-01-01 |
| 종료일 | 2025-12-31 |
| 시간 단위 | 일별 |
| 가격 기준 | 수정주가 |
| 필요한 정보 | 종목코드, 거래일, 시가, 고가, 저가, 종가, 거래량 |

## 기준을 정한 이유
- 기존 한국투자증권 계좌를 활용할 수 있다.
- 완료된 한 해로 기간을 고정해 결과를 비교하기 쉽게 한다.
- 우선 5개 종목으로 수집·검증 과정을 익힌다.
- 수정주가를 선택해 주식분할 등 가격 조정의 영향을 다룬다.
  구체적인 조정 범위는 제공처 기준을 따른다.

## 이후 구현 시 확인할 사항
- 기간별시세는 요청당 최대 100건이므로 기간을 나눠 수집해야 한다.
- 달력상의 모든 날짜에 거래가 있는 것은 아니다.
  거래일 기준으로 확인하고 없는 날짜를 임의로 채우지 않는다.
- 동일한 종목·거래일이 중복되지 않도록 확인한다.
- 수정주가는 이후 기업행사에 따라 과거 값이 바뀔 수 있으므로
  수집 시점과 조회 조건을 함께 기록한다.
- 상세 열 이름·자료형과 저장 구조는 31일차에 정한다.

## 현재 진행 상태
- 수집 대상과 범위를 정했다.
- 실제 주가 API 요청은 아직 하지 않았다.
- API 서비스 신청과 인증키 발급 여부는 30일차에 확인한다.
- 인증키와 실제 시세 데이터의 Git 관리 기준은 수집 전에 확인한다.
