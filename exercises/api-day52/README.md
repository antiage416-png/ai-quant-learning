# 8주차 52일차 — 종목·기간 입력 검증과 일봉 조회 API

## 목적과 흐름

종목코드와 시작일·종료일을 입력받아 기존 가격 CSV의 해당 기간을 반환한다.

입력 → 종목 형식·날짜·지원 종목 검사 → CSV 읽기 → 기간 선택 → JSON 응답

- 코드: main.py
- 경로: GET /api/prices
- 필수 입력: stock_code, start_date, end_date
- 자료: data/stock-day33/clean/{종목코드}_2025_clean.csv
- 지원 종목: 005930, 000660, 005380, 035420, 055550

## 구현 규칙

- 종목코드는 숫자 0~9로 이루어진 여섯 자리 문자열이다.
- 날짜는 date 자료형으로 받는다.
- 시작일이 종료일보다 늦으면 오류를 응답한다.
- 시작일과 종료일 당일을 모두 포함한다.
- 지원 목록에 없는 종목은 조회를 거절한다.
- 필요한 CSV가 없으면 오류를 응답한다.
- 선택한 행이 없으면 selected_rows는 0, prices는 빈 리스트다.

## 확인한 결과

- 필수 입력 누락과 존재하지 않는 날짜: 오류 응답 확인.
- 시작일·종료일 역전과 문자가 섞인 종목코드: 오류 응답 확인.
- 지원하지 않는 종목 999999: 오류 응답 확인.
- 삼성전자 1월 2일~6일: 3행, 날짜·시가·종가 원본 대조 통과.
- 삼성전자 1월 3일 하루: 1행, 시가·종가 원본 대조 통과.
- 삼성전자 1월 4일~5일: 0행과 빈 리스트 확인.
- SK하이닉스 1월 2일 하루: 1행, 전체 필드 원본 대조 통과.
- 두 종목의 source_rows: 각각 242행.

## 배운 점과 수정한 오류

- table은 CSV 전체 표, selected는 요청 기간에 해당하는 표다.
- 종목코드를 문자열로 읽어 앞자리 0을 유지한다.
- Path로 경로를 만들고 pandas로 표를 읽고 선택한다.
- to_dict(orient="records")로 각 행을 딕셔너리로 변환한다.
- 지원 종목 목록의 이름을 찾지 못하는 NameError를 수정했다.
- 작은 코드 블록을 직접 붙여넣고 실행하며 처리 흐름을 설명했다.

## 범위

기존 CSV를 조회했으며 원본 수정·외부 가격 수집·실제 주문·성과 계산은 하지 않았다.
파일 누락 응답은 구현했으나 파일을 제거하는 검사는 수행하지 않았다.
자료 범위를 벗어난 요청, 일부 구간의 자료 부족, 손상된 CSV의 처리는 후속 보완 대상이다.
