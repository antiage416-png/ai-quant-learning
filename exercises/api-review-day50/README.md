### 확인한 파일과 역할

| 파일·함수 | 확인한 역할 |
|---|---|
| app/backend/main.py | 서버 생성과 요청 경로 등록 |
| main.py의 health_check() | 정해진 상태 응답 반환 |
| app/backend/routers/quant.py | 분석 관련 요청 형식과 처리 함수 |
| quant.py의 BacktestRequest | 이동평균 기간·자료 길이의 기본값과 범위 정의 |
| quant.py의 quant_backtest() | 가상 가격 생성·분석·그래프·지표 반환 |
| app/src/Backtest.py | 가상 가격 생성·전략·지표·그래프 기능을 함수로 구분 |

상태 확인 함수는 {"status": "ok"}를 반환한다.
데이터베이스·가격 자료·백테스트 계산의 정상 여부까지 검사하지는 않는다.

include_router는 기능별 요청 경로를 앱에 등록한다.
등록 자체가 분석 실행을 의미하지는 않는다.

### 백테스트 API의 실제 흐름

이동평균 기간·자료 길이 입력
→ 입력 형식과 범위 검사
→ 난수로 가상 가격 생성
→ 이동평균·보유 상태·수익률 계산
→ 성과 지표와 그래프 반환

quant_backtest()는 app/src/Backtest.py를 호출하지 않고
함수 안에서 직접 계산한다.

가상 가격에서 계산한 결과이므로 삼성전자의 실제 과거 성과라고 설명할 수 없다.

### 입력 검증에서 배운 점

BacktestRequest의 개별 허용 범위는 다음과 같다.

- fast_ma: 5~60, 기본값 20
- slow_ma: 20~200, 기본값 60
- n_days: 252~5040, 기본값 1260

fast_ma=60, slow_ma=20은 각각의 범위에는 들어간다.
하지만 짧은 기간 < 긴 기간이라는 전략 조건에는 맞지 않는다.

보여준 요청 클래스에는 두 값의 순서 검사 조건이 없었다.
우리 구현에서는 개별 범위와 값 사이의 관계를 함께 검사해야 한다.
분석 실행 전에 입력 오류를 알려주는 방식으로 설계한다.

### 우리 실습과의 차이

| 항목 | 참고 백테스트 API | 기존 학습 실습 |
|---|---|---|
| 가격 자료 | 난수로 생성한 가상 가격 | 저장된 삼성전자 실제 일봉 |
| 전략 표현 | 이동평균 대소 관계에 따른 보유 상태 | 교차 신호에 따른 주문 |
| 수익 계산 | 전날 보유 상태와 종가 간 일간수익률 사용 | 다음 거래일 시가·현금·정수 수량·비용 반영 |
| 결과 전달 | 지표와 그래프를 API 응답으로 반환 | CSV와 그래프 저장 |

같은 이동평균 전략이라는 이름만으로 계산 조건이 같다고 판단하지 않는다.
참고 구조를 활용하되 기존 자금·비용·교차·체결 조건을 유지한다.

### 우리 코드에 필요한 역할

| 역할 | 필요한 기능 |
|---|---|
| API 요청 처리 | 요청을 받고 필요한 기능 호출 |
| 입력 검증 | 종목·기간·전략 조건 확인 |
| 데이터 읽기 | 저장된 일봉이나 결과에서 요청 대상 선택 |
| 분석 | 기존 조건으로 신호·계좌·성과 계산 |
| 응답 만들기 | 결과를 JSON으로 전달 |

저장 결과 조회와 새 계산 실행을 구분한다.

- 조회: 기존 결과를 읽어 반환한다.
- 실행: 요청 조건으로 분석하고 결과를 저장·반환한다.

CSV에서 날짜 범위에 맞는 행을 선택하는 코드는 데이터 읽기 역할이다.
이를 호출해 결과를 전달하는 전체 기능은 저장 결과 조회다.
