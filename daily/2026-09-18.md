## 실제 실행한 내용과 결과

### 1. 환경 확인

CPU i5-7300HQ, RAM 8GB, NVIDIA GTX 1050 2GB, Windows 10 Pro 22H2를 확인했다. PowerShell의 `wsl --status`, `wsl --list --verbose` 결과는 기본 버전 2·설치된 배포판 없음이었다. `Get-PhysicalDisk`에서 약 120GB SSD와 1TB HDD를 확인했다. 자세한 비교는 [환경표](../docs/environments.md)에 있다.

### 2. 개인 자료 이동

개인 자료 두 폴더, 총 4,593개 파일을 D로 복사했다. 전체 파일 SHA-256 비교 후 C 원본을 정리했고, 기존 C 경로에는 D를 가리키는 정션을 남겼다. 실제 확보 공간은 3.51GB였다. 두 경로는 같은 자료를 가리키므로 한쪽을 중복 백업으로 생각하고 삭제하면 안 된다. 개인 자료의 파일명·해시 목록은 Git에 올리지 않았다.

### 3. 캐시 정리

pip 다운로드 캐시, NVIDIA DXCache, 일부 VS Code 캐시·오래된 설치 파일 541개를 정리했다. 최근 이틀 안에 변경된 파일과 실행 중인 앱의 캐시는 제외했다. 실제 확보 공간은 1.48GB였고, 삭제 대상이 사라졌는지 재확인했다. Chrome·Discord의 로그인 정보, Codex 기록, 설치된 개발 환경은 건드리지 않았다.

### 4. Anaconda 재설치와 연결

1. 기존 환경 목록·패키지 버전·PATH·시작 메뉴 바로가기·커널 정의를 PC 2 로컬에 백업했다.
2. 공식 Anaconda 2025.12-2 Windows 설치 파일의 SHA-256을 검증했다.
3. `D:\hp\DevTools\anaconda3`에 같은 버전을 설치하고 LightGBM 4.6.0, XGBoost 3.2.0을 추가했다.
4. 기존 391개 Python 패키지 버전과 새 설치의 버전이 일치하는지 확인했다.
5. Jupyter `anaconda-d` 커널을 등록하고 Anaconda 관련 사용자 PATH·시작 메뉴 바로가기를 D로 연결했다.
6. C의 기존 설치를 임시 이름으로 바꿔 이전 경로가 없는 상태에서 D의 독립 실행을 검사했다.
7. 검사를 통과한 뒤 C 설치·임시 보관 폴더·오래된 등록 정보를 정리했다.
8. 실제 경로 부재, D Python 존재, conda 환경 목록과 Windows 등록 정보를 다시 확인했다.

## 오류와 해결

- Codex 실행 환경에서 시스템 조회, D 폴더 생성, 설치 프로그램 임시 파일 처리와 C 폴더 이름 변경이 일부 거부됐다.
- 허용된 경로 권한으로 가능한 작업을 진행하고, 설치·최종 정리 등 제한된 단계는 검증 조건이 포함된 PowerShell 스크립트를 사용자가 직접 실행했다.
- 실패한 D 설치는 별도 폴더로 보존한 뒤 새 설치를 진행했다. 검증 전 C 설치를 삭제하지 않았다.
- 최종 사용자 실행 결과는 `Completed`, `OriginalDeleted=True`, `IndependentNotebookPassed=True`, `PackagesMatched=True`, 등록 경고 없음이었다.
- 예전 ai120 환경은 이미 없었으며 이번 작업으로 복원하지 않았다. Jupyter에서는 Python (Anaconda D)를 선택한다.
