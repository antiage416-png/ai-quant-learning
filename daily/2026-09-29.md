## 3주차 17일차: 로그와 수집 결과 기록

### 실습
- logging으로 시간·수준·메시지를 출력했다.
- StreamHandler로 터미널에, FileHandler로 파일에 기록했다.
- mode="a"로 실행 기록이 누적되는 것을 확인했다.
- 정상 페이지와 없는 페이지에 요청해 실제 결과를 기록했다.
- tail 명령으로 저장된 로그를 다시 확인했다.

### 검증 결과
- 정상 페이지: HTTP 200, 명언 10개.
- 없는 페이지: HTTP 404.
- 최종 요약: 성공 1건, 실패 1건, 명언 10개.
- collection.log에서도 동일한 결과 확인.

### 배운 점
- INFO는 진행 상황, WARNING은 주의 사항, ERROR는 실패를 기록한다.
- logger.error() 자체가 프로그램을 종료시키지는 않는다.
- 로그는 성공·실패를 자동 판단하지 않는다.
  코드에서 상황에 맞는 기록을 남겨야 한다.
- 성공·실패 건수는 페이지 단위, 명언 건수는 추출 항목 단위다.

## 3주차 19일차: 고유 제약과 upsert

### 실습
- 본문·작성자 조합에 UNIQUE 제약 적용.
- 새 데이터는 INSERT, 기존 데이터는 출처 주소를 UPDATE하도록 구현.
- 같은 코드를 재실행해 중복 행이 생기는지 확인.
- 출처 주소를 변경해 기존 행이 갱신되는지 확인.

### 검증 결과
- 첫 실행: 1행 삽입.
- 동일 데이터 재실행: 행 수 1, id 1 유지.
- 출처 변경 후 실행: 행 수와 id는 유지되고 주소만 갱신.

### 배운 점
- id가 고유해도 같은 내용의 중복 저장을 막지는 못한다.
- UNIQUE(text, author)는 같은 본문·작성자 조합의 중복을 막는다.
- ON CONFLICT는 고유 제약과 충돌했을 때의 동작을 지정한다.
- excluded.source_url은 이번에 삽입하려던 데이터의 출처 값이다.
- 이번 실습은 작성자가 반드시 있는 연습 데이터를 사용했다.

### 결과물
- exercises/upsert-day19/upsert_demo.py
- 로컬 DB: exercises/upsert-day19/practice.db

 ## 3주차 20일차: 실패 URL 저장과 선택적 재실행

### 실습
- 정상 주소와 없는 주소를 요청했다.
- 실패한 주소와 이유를 failed_urls.json에 저장했다.
- 실패 목록만 읽어 각 주소를 한 번씩 다시 요청했다.
- 여전히 실패한 항목을 remaining_failures.json에 저장했다.

### 검증 결과
- 최초 실패 목록: HTTP 404 주소 1건.
- 재실행 대상: 1건.
- 재실행 성공: 0건.
- 남은 실패: HTTP 404 주소 1건.
- 남은 실패 파일의 내용까지 확인했다.

### 배운 점
- json.dumps는 Python 데이터를 JSON 문자열로 변환한다.
- json.loads는 JSON 문자열을 Python 데이터로 복원한다.
- 같은 실행 안의 재시도와 파일을 이용한 나중 재실행은 다르다.
- 404는 재요청만으로 해결되지 않을 수 있다.

### 현재 한계
- 재실행 코드는 항상 최초 failed_urls.json을 읽는다.
- 재실행 후 성공한 항목이 빠지는 경우는 아직 시험하지 않았다.

- 기본 페이지의 Response에는 명언과 작성자의 HTML 요소가 있었다.
- JavaScript 페이지의 Response에는 script 안에 명언 데이터가 있었다.

- Elements는 브라우저가 구성한 현재 DOM을 보여준다.
- BeautifulSoup은 JavaScript를 실행하지 않는다.
- 요소가 0개여도 응답 안에 데이터 자체가 없다고 단정할 수 없다.
- JavaScript로 요소를 만든다고 반드시 별도 API 요청이 필요한 것은 아니다.

## 4주차 24일차: 요소 대기와 클릭·페이지 이동

### 실습
- JavaScript 페이지의 첫 명언이 visible 상태가 될 때까지 기다렸다.
- inner_text()로 브라우저가 만든 요소의 글자를 읽었다.
- Next 링크의 href를 가져와 urljoin으로 목적지 주소를 만들었다.
- click()으로 링크를 클릭하고 wait_for_url()로 이동을 확인했다.
- 새 페이지의 첫 명언이 나타난 뒤 이동 전 내용과 비교했다.

- URL 이동 확인과 필요한 요소의 표시 확인은 구분한다.
